# 2026-09-18｜本文の代表色を分ける修正

## 基準にしたファイル

利用者が最後に渡した `yomitoki-public jintou.zip` の `yomitoki-public/index.html`。以前のZIPや公開サイトを基準に置き換えていない。元ファイルのハッシュは `source-manifest.json` に記録している。

## 確認した原因

この版には、すでにAPI出力の `primary` を本文色に使う実装がある。しかし、`primary` が「根拠なき断定」を指定した場合、あるいは有効な指定がない場合には、赤が代表色になる。後者では `FLAG_ORDER` の先頭が「根拠なき断定」だった。

実行画面からは `primary` の生の値は読めないため、今回の実行がどちらだったかは確定していない。一方で、画像に表示されていた「根拠なき断定＋過剰肯定」「根拠なき断定＋出どころなき引用」「根拠なき断定＋過剰な未来予測」を渡すと、この表示上の偏りを再現できた。

## 修正

`cleanFlags()` と `displayFlag()` を分離した。判定結果の `flags` と、本文で代表にする一色を別に扱う。

| 検出された指摘 | 本文の代表色 |
| --- | --- |
| 根拠なき断定＋過剰肯定 | 緑 |
| 根拠なき断定＋出どころなき引用 | 藍 |
| 根拠なき断定＋過剰な未来予測 | 琥珀 |
| 根拠なき断定のみ | 朱 |
| 具体区分が複数 | 有効な具体区分の `primary` を採用。なければAPIの返却順で一つ。 |

「根拠なき断定」より他の区分が重い・軽いという順位ではない。複数の指摘の中で、表示上より具体的な種類を代表にする方針。元の `flags`、本文、文区分、理由、書き換え案を変更しない。検出されていない区分を補って色数を増やす処理はない。

凡例にもこの表示ルールを記載した。表示結果を確認しやすいよう、各セグメントには `data-display-flag` が付く。

## 変えていないもの

- `CRITERIA`、`buildPrompt`、`buildRecheckPrompt` は元版と同一。検品・書き換えの指示は変更していない。
- Geminiの接続先・内部モデル名・生成設定・呼び出し回数は変更していない。
- 四色の色値、2pxの本文下線、赤い取り消し線、明朝見出し、方眼、朱印、ロゴは維持。
- 小字のクリック・キーボード操作は維持。
- APIを用いて分類のぶれや誤検出を改善したという修正ではない。

## 写真のサンプルとデモ

本体の保存サンプルを写真の例に差し替えた。`demo/index.html` は同じ表示ロジックを使う独立デモ。APIキー欄・本文入力欄・Gemini呼び出し・キー保存処理を含まない。

データの出所は `fixtures/photo-screen-snapshot.json` の `provenance` に記録した。質問文は会話で提示した写真の例題。判定・理由・文区分・書き換え案は利用者の実行画面から目視で再構成した。生のAPI応答JSONや実際の送信ログは受け取っていないため、それらを保存・検証したとは扱わない。空白、数字の全半角、取り消し線に指定された語句の厳密な境界も生JSONとの一致を保証しない。

画面で読めなかった `primary`、全体所見 `summary`、二周目の `segments` は推測して作り足していない。二周目は実行画面に出ていた結果文言だけを「保存例の二周目の検品」として表示する。未取得の二周目JSONを空配列にして成功扱いする処理ではない。

このデモの入力文は説明用に作られた架空例。文中の「写真の専門家」の発言は実在する発言として提示しない。

本体サンプルから戻る際は、元の質問と返答を組で復元する。保存先はページ内の変数だけで、入力を新しく永続保存しない。

## 実際に実行した確認

`test-results/` に実行レポートを同梱した。

- 既存のNode.js回帰テスト：7グループ。模擬通信、2回検品、90秒タイムアウト、エラー復帰、HTMLエスケープ等。
- 表示ロジックのNode.jsテスト：10グループ。指摘集合・順序・代表指定の448組み合わせを含む。
- Chromium：13グループ。元版の赤3本の再現、修正版の3色、下欄の赤3件の保持、書き換え案の保持、入力復元、APIが赤だけを返す場合、模擬429後の復帰、コピー、小字操作等。
- 本体と独立デモの両方で、320・375・390・480・768・1280px幅の横はみ出しがないことを確認。

**実Geminiへのリクエストは0回。** API応答とクリップボードは模擬。ブラウザ確認はHTMLをメモリに読み込む方式で、外部フォント通信は遮断し、環境内の日本語フォントで代替した。実機Safari/Chrome、Google側の現在の利用可否・利用枠、モデルの判定品質、GitHub Pages上の配信状態は今回の検証対象ではない。公開サイトは変更していない。

## 今回の修正で解決しないこと

モデルが「根拠なき断定」しか返さないときは、そのまま赤を表示する。他の指摘を出すように判定結果を書き換えない。同じ文章の再実行で、検出箇所・区分・理由が変わる可能性を、この表示修正で解消したとは主張しない。
