# よみとき

AIの返答を読み解き、根拠の不足や過剰な同意を検品する、単一HTMLのツールです。TAKIBI lab。

文章の区分と検品の指摘を分けて表示し、書き換え案をもう一度検品します。特定の職業・立場・個人を評価するための道具ではありません。点数や人物の順位は付けません。

## 使い方

1. `index.html`をブラウザで開きます。
2. 「サンプルで見る」で写真の表示例を確認できます。この操作はAPIキー不要で、APIを呼び出しません。「自分の入力に戻る」で元の質問と返答を復元できます。
3. 自分の文章を検品するときは、「APIキーの設定」に自分のGemini APIキーを入力します。
4. 元の質問・文脈とAIの返答を貼り付け、「測り直す」を押します。
5. 書き換え案と二周目の指摘を確認します。問題が残った場合は、人が最終的な文章を判断します。

元の質問・文脈は入力推奨ですが、必須ではありません。空欄や空白だけで実行した結果には「文脈なしでの検品：元の質問や会話は参照していません。」と表示します。表示は実行時の入力に基づき、後から入力欄を編集しても変わりません。文脈の不在だけで根拠の不存在やAIによる付加を確定せず、提供情報から確認できない場合と区別するよう、初回・二周目の共有基準に補足しています。

Gemini専用です。検品対象の返答は、どのAIのものでも入力できます。APIキーを別サービスのものに替えても、接続先は切り替わりません。

## 判定の考え方

小字は「事実に関する記述・推論・意見・励まし・質問文」を表します。「事実」は検証可能な事柄について述べているという区分であり、正しさを確認済みという意味ではありません。

色の下線は「根拠なき断定・過剰肯定・過剰な未来予測・出どころなき引用」を表します。どの区分の文も検品対象です。

「根拠なき断定」と他の区分が重なる場合、本文には他の区分の色を出し、下の指摘欄にはすべての指摘を残します。赤だけの判定は赤のままです。複数の具体区分がある場合は、有効な代表指定（`primary`）を尊重し、指定がなければAPIの返却順を使います。重大さの順位や色数の均等化ではありません。

- 「世間では」「そう考える人が多い」なども、評価や頻度についての主張として根拠を確認します。
- 職業・肩書きだけによる人や人生の格付けへの同調は、対象を問わず同じ基準で見直します。具体的な条件に基づく比較や個人の好みとは区別します。
- 傷ついた経験の引用と、引用された評価への賛同は区別します。
- 語尾を弱めたり、別の褒め言葉に置き換えたりしただけでは、根拠不足の解消とは扱いません。
- 根拠が示されていないことと、その主張が虚偽だと確定したことは区別します。

判定の指示は`index.html`の`CRITERIA`、`buildPrompt`、`buildRecheckPrompt`で公開しています。

展示で質問の多かった処理の流れ、8軸と「問い」の関係、表示色の選び方、検証済みの範囲は[「よみときは、どう判定しているか」](docs/HOW_IT_WORKS_JA.md)にまとめています。

## 処理と限界

実検品は原則2回のAPI呼び出しです。初回で検品と書き換え、二周目で再検品を行い、追加の自動修正はしません。初回で失敗した場合は二周目へ進みません。各API呼び出しは本文の受信まで含めて90秒を上限に待機します。処理中はサンプルの切り替えを止めます。

判定には誤検出や見逃しがあり、同じ入力でも結果が変わることがあります。外部検索で出典を照合する機能はありません。「指摘なし」は、真偽や妥当性を保証する表示ではありません。提示された出典そのものの正しさも別途確認が必要です。

## データとAPIキー

- 「測り直す」を押すと、質問・AIの返答・判定の指示をGoogleのGemini APIへ直接送ります。再検品では書き換え案と初回の指摘も送ります。
- アプリ独自のサーバー、アクセス解析、入力文章の保存機能はありません。ページ表示時にはGoogle Fontsからフォントを読み込みます。リンクを開く操作ではリンク先へアクセスします。
- APIキーは、このサイトを開いたブラウザの`localStorage`に保存します。HTMLファイルに書き込まれるわけではありません。共用端末では利用後にキー欄を空にして保存値を消してください。
- キーはGoogleへの認証ヘッダーに使います。リクエストURLには含めません。ブラウザで扱うキーを、端末や同じサイト内のスクリプトから完全に秘匿する仕組みではありません。
- 利用者が自分のキーを入力する方式です。運営者の共通キーをHTMLへ埋め込んで配布する設計ではありません。キー、入力を含むログ、個人的なスクリーンショットはリポジトリに追加しないでください。

APIの利用枠・料金・データの取り扱いはGoogle側の設定と規約に従います。

- [Google AI Studio：キーの取得・管理](https://aistudio.google.com/apikey)
- [Google公式：APIキーと管理上の注意](https://ai.google.dev/gemini-api/docs/api-key)
- [Google公式：料金](https://ai.google.dev/gemini-api/docs/pricing)
- [Google公式：利用規約](https://ai.google.dev/gemini-api/terms)

## GitHubへ置くファイル

このフォルダの`index.html`、`README.md`、`.gitignore`、`tests/`が公開用の一式です。上位の作業フォルダやバックアップを一緒にアップロードする必要はありません。GitHub Pages等の静的配信を利用する場合も、APIキーはファイルに書き込まず利用時に入力します。

### 本体とデモの配置

本体を差し替えるファイルはルートの `index.html` です。`demo/index.html` は独立したAPI不要の表示デモです。同じリポジトリの `demo/` に置くと、本体とは別の `/yomitoki/demo/` で開けます。デモから本体へのリンクは `../index.html` です。別のリポジトリやURL構成で公開する場合は、このリンクだけ公開先に合わせて変更してください。

両HTMLはそれぞれ単独で動く形式です。`fixtures/` は記録用で、表示時に別途読み込むファイルではありません。外部フォントが使えない場合は端末のフォントへ切り替わります。フォントファイルは配布していません。

### 保存デモの出所

写真の判定・理由・書き換え案は、利用者が提供した実行画面から再構成しました。元の質問は会話で用意した例題です。生のAPI応答JSON・送信ログ・二周目のセグメント一覧は未取得です。画面でも「実行結果の画面から再構成した表示例」と明記しています。いまその場で測った結果、または同じ入力なら毎回一致する正解としては提示しません。入力文は説明用の架空例で、専門家の発言は実在の引用ではありません。

詳細は `CHANGES.md` と `fixtures/photo-screen-snapshot.json` の `provenance` を参照してください。

この一式にはライセンスファイルを同梱していません。公開だけで自由な再利用を許諾したとみなす説明はしていません。

## 開発・検証

ビルドやパッケージのインストールは不要です。テストはNode.jsの標準機能だけで動きます。

```sh
node tests/app.test.cjs
node tests/display.test.cjs
node tests/context.test.cjs
```

テストは模擬通信と簡易DOMを使い、サンプルの通信ゼロ、2回の検品、割り込み防止、正常・失敗・タイムアウト時の終了処理、出力のHTMLエスケープを確認します。実際のキーは不要で、API利用枠を消費しません。

実行済みの結果は `test-results/` にあります。Chromiumでは、本体とデモの両方を6画面幅で確認しました。API応答は模擬し、Googleには接続していません。ブラウザテストを再実行する場合は、Playwright for Python と Chromium がある環境で次を実行します。

```sh
python tests/browser_test.py --chromium /usr/bin/chromium
```

このテストは全外部通信を遮断または模擬します。HTMLをメモリに読み込む検証であり、公開サイトの確認ではありません。実Geminiによる判定精度・実機ブラウザ・GitHub Pages上の動作は今回未検証です。
