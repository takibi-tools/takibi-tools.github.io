# よみとき 試験版（next）

https://takibi-tools.github.io/yomitoki/next/

「何回測っても結果がそろう」ことを目指した試験版。本番（`../index.html`）とは別のページで、本番には影響しない。2026-11-02 作成。

## 本番との違い

- 文の区切りをプログラムで決める。「。！？!?」と改行で区切り、かぎ括弧などの内側では区切らない。モデルには番号付きの区切りを渡し、番号ごとの区分と指摘だけを答えさせる（区切りの本文は書き写させない）。
- 出力の形を responseSchema で固定する。区分と指摘は決められた名前からしか選べない。
- 生成の揺れを止める：temperature 0、topK 1、seed 固定、thinking なし（考える処理を常に止める）。
- 検品は1回だけ。多数決はしない。
- 「精度を上げる」は、二周目の検品（と、問題が残ったときの直し直し）だけを足す。
- 指示文に、各指摘と区分の境目の例（付ける例・付けない例）を足した。
- 直し直しは、書き直した全文だけを返させる。
- 区分の定義に二つ書き足した（11/2）。推測：言い切りの形でも、内容が先の見込みや確かめられていない予想なら推測とする。意見：口調が強い・煽っているというだけで意見にしない。煽り文で、言い切った予測まで意見に分類されていたため。

## 分かっている限界

- Geminiは temperature 0・seed 固定でも、完全に同じ結果を返すとは保証していない。
- 本番で temperature を 0.2 にしたのは、0 では見逃しの側に結果が固まる例があったため（fixtures/eval-cases.md）。試験版ではそれを承知で 0 にしている。
- 区切りを文単位に固定したため、一つの文の中で主張と問いが混ざる場合などに、節で分けることはできない。
- Geminiへの実際の送信は、作成時には確かめていない。応答を差し替えた画面テストでのみ確かめた。

## 確かめ方

同じ文章を同じ物差しで3〜5回測り、区分と指摘が文ごとにどれだけ一致するかを数える。
